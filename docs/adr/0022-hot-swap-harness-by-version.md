# 0022 改良の対象を、統合ブランチの版ごとに子プロセスとして動かす

日付: 2026-11-06

## 状況

ハーネスが自分を改良しても、その改良が効くのは利用者がサーバーを起動し直したときだけだった。論点エージェント・分解役・解答役のコードは、起動した時点の作業ツリーから読み込まれ、プロセスに残り続けていた。ADR 0014 は、固定部が採用した版をコミットから取り出して動かすと決めていたが、最小の流れ（ADR 0021）では後回しにしていた。

## 決定

- 固定部と改良の対象をディレクトリで分ける。
  - `server/`: 固定部。サーバー、中継、対話の状態、流れの順番の制御（作業ツリー、検査、コミット、差し戻し、保留、push）、版の選び方。長く動くプロセスに残り、変更は利用者がマージして起動し直したときだけ効く。
  - `harness/`: 改良の対象。論点エージェント・分解役・解答役のプロンプト、ツール、ループ。
  - `shared/`: 2つの間の約束。対話の状態の形（`dialog.ts`）と、改良の対象が使ってよい操作（`contract.ts` の `AgentStore`）。
- 固定部は、エージェントを1回動かすたびに、hypharness 自身の統合ブランチの先端（検査を通ったコミットだけが積まれる）を `~/.hyph/versions/` に取り出し、`harness/worker.ts` を子プロセスとして起動する。課題の途中で版を変えないよう、入れ替える単位はエージェントの1回の実行にする。
- 子プロセスは、モデルを中継のソケット、対話の状態を固定部の受け口のソケット（`host-<プロセス番号>.sock`）を通して使う。モデルの認証情報は渡さない。
- 子プロセスが結果もエージェントとしての誤りも書かずに終わったら、その版を壊れた版として記録し、作業ツリーの版で動かし直す（ADR 0006 の取り消しを、その場で行う）。

## 結果

- 統合ブランチに改良が積まれると、次に動くエージェントからその改良が効く。
- 約束（`shared/`）を変える改良と、固定部（`server/`）を変える改良は、利用者のマージを待つ。
- `node_modules` は固定部のものを共有する。依存を足した版は起動できずに落ち、作業ツリーの版で動く。
- 子プロセスはまだ隔離環境に入れていない。
