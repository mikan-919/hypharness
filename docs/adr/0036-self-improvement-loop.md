# 0036 ハーネスの自己改良ループを1つに組む

日付: 2026-11-06

## 状況

オフライン層は、ハーネスのコードとプロンプトを改良する層として決まっている（用語集）。改良の進め方を決める文献が複数ある。すべてを別々のループとして持つと、同じ評価を何度も回すことになる。

- Self-Harness（arXiv:2606.09498）: 弱点発見・ハーネス提案・回帰テストによる検証の3段階。
- Meta-Harness（arXiv:2603.28052）: 提案役が、過去の候補のコード・スコア・実行の記録をファイルとして読む。
- ModularRSI（arXiv:2609.14857）: ハーネスを5モジュールに分け、モジュールごとに変更し、統合する。
- RRSI（arXiv:2609.24972）: 提案と選択を正則化する（束ねる変更の制限、探索の誘導、critic、pruner）。
- Darwin Gödel Machine（arXiv:2505.22954）: 候補のアーカイブを持ち、そこから選んで系統を分ける。
- AIDE²（arXiv:2609.26457）: 自分のコードを書き換え、隠れた評価で最良を残す。採用した版が次の周の出発点になる。
- GEPA（arXiv:2507.19457）: 自然文の振り返りでプロンプトを改良し、Pareto の候補群を残す。
- SpecForge（arXiv:2610.15708）: 振る舞いの仕様を失敗から直し、依存の下流から直す。
- A Self-Improving Coding Agent（arXiv:2504.15228）: 変更・評価・採用の最小の1周。

## 決定

- 自己改良は1つのループにする。1周は、弱点発見 → 提案 → 回帰テスト → 採用 → アーカイブの順。
- 弱点発見は、解答役の共有文脈と実行の記録から失敗の型を集める（Self-Harness）。
- 提案は、5モジュール（エージェントループ、ツール使用、観察管理、文脈管理、完了判定）ごとに1つ作る（ModularRSI）。提案役は `~/.hyph/evo/` の過去の候補のコード・スコア・実行の記録をファイルとして読む（Meta-Harness）。
- 提案の制限: 1候補が束ねる変更は最初3個まで、10周ごとに1個へ減らす。失敗した変更を提案の入力に入れる。3周続けて改善が無ければ未探索のモジュールへ回す（RRSI）。critic が課題に固有すぎる提案を弾き、pruner が改善 0 以下・費用増・不要になった変更を捨てる。
- 採用は、既存の検査と検証生成役のテストで報酬が 1 の候補だけ（Self-Harness）。
- 採用した候補は `~/.hyph/evo/archive/` に残し、次の周はアーカイブから1つ選んで出発点にする（Darwin Gödel Machine）。採用した版が次の周の出発点になる（AIDE²）。効果は提案に使わなかった課題でも測る。
- プロンプトの改良は、自然文の失敗の診断から候補を作り、複数の課題での通過数で Pareto の候補群を残す（GEPA）。
- 仕様は `docs/specs/<モジュール>.md` に置き、失敗したテストから直す。直す順は依存の下流から。失敗の種類ごとに別の候補を作る（SpecForge）。
- `bun run evolve` で1周を回す。1周の費用に上限を置く。固定部は変更の対象にしない（ADR 0014）。

## 結果

- 改良の1周が1つのコマンドで回り、各文献の仕組みは役割として1回ずつ使われる。
- 1周の費用が大きいため、周の回数と1周の上限を決めて回す必要がある。
- 変更の提案がモジュールに分かれるので、どの変更が効いたかを記録から辿れる。統合の段階でモジュール間の衝突を解く処理が要る。
