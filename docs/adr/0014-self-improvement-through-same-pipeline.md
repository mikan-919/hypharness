# 0014 固定部を最小にし、ハーネスの中身はすべて同じ流れで改良する

日付: 2026-11-06

## 状況

オフラインでは、ハーネスのコードとプロンプトを改良する（ADR 0004）。改良のための専用の仕組みを作ると、旧実装の `evolve` などと同じ固定費が戻る。固定部と改良の対象をディレクトリで分けるだけでは、改良の対象のコードが固定部を呼ばずに済ませたり、渡す値を細工したりできる。一方、固定部が流れと入出力の形を決めると、役を足す・流れを組み替えるといった変更ができない。

## 決定

- 固定部は、既定のブランチの版でホストとして動く。固定部は次だけを持つ。
  - モデルの呼び出しの中継（費用の記録、課題1つあたりの上限、停止）
  - 隔離環境の起動
  - 統合ブランチへの push
  - 遅れて取れる信号の集計（origin の履歴を読む）
  - 採否と取り消しの判定
- 対話の層、分解役、方針役、検証生成役、解答役、DeLM の組み方、流れそのもの、すぐに取れる信号の計算、経験の一覧は、すべて改良の対象とする。固定部が採用した版をコミットから取り出し、隔離環境で動かす。
- 固定部とハーネスの約束は、「対象のリポジトリと最終目的の文書を受け取り、統合ブランチにコミットを積む」の1つだけにする。隔離環境から外へは、この入出力とモデルの呼び出しの中継（Unix ソケット）だけを通す。
- hypharness のリポジトリに、ハーネスを改良する最終目的の文書を置き、他のリポジトリと同じ流れで変更を作る。
- 固定部を変えたコミットは自動では採用せず、利用者が統合ブランチを既定のブランチにマージしたときにだけ反映する。

## 結果

- すぐに取れる信号はハーネス自身が計算するため、改ざんされうる。採用の判断にだけ使い、取り消しは、利用者のマージと編集で決まる遅れて取れる信号で行う（ADR 0006）。
- 悪い版を取り消すまでに、遅れて取れる信号の分だけ時間がかかる。その間の被害は、統合ブランチの上と、課題1つあたりの費用の上限の範囲に限られる。
- 固定部が隔離環境から読み書きされないことを、テストで確かめる。
