# 0038 実行中でも FINAL_GOAL を書き換えられ、書き換えで再始動する

日付: 2026-11-06

## 状況

`server/app.ts` の `/api/goal` は、実行中かどうかを確かめずに `store.editGoal` を呼ぶ。`harness/topic.ts` の `runTopic` は、次のモデル呼び出しの前に `editsSince` で差分を会話に入れる。`harness/index.ts` のコメントは「開始可になった論点は、利用者がその後に本文を書き換えても起き直さない」と書いてある。つまり、保存はできるが、一度 `ready` になった論点は書き換えても動かない。

## 決定

- `/api/goal` は実行中でも保存を受け付ける。版の検査は変えない。
- 保存したら、その論点の実行を再始動する。再始動の条件は利用者の書き換えだけ。エージェント自身の書き換えでは起こさない。
- 再始動のとき、`ready` を false に戻し、状態を `researching` にする。
- 論点ごとに実行は1つだけにする。実行中に新しい書き換えが来たら、実行中のモデル呼び出しを打ち切らず、その呼び出しが終わってから再始動する。待っている質問があれば取り下げ、その質問への答えは受け付けない。
- 差分は `seen` の版で一度だけ渡す。同じ差分を二度渡さない。
- 画面は、質問待ちのときも保存ボタンを押せるようにする。保存の結果を「保存した（版 N）」と出す。

## 結果

- 利用者は、論点エージェントの返答を待たずに本文を直せる。直した内容は、次の実行の最初にエージェントへ差分で届く。
- 実行中の呼び出しの分の費用は、書き換えても無駄になる（打ち切らないため）。
- 質問を取り下げるため、利用者が質問に答えている途中で本文を書き換えると、その答えは捨てられる。
