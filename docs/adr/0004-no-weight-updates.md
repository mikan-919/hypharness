# 0004 重みを更新せず、共有文脈から経験の一覧を書く

日付: 2026-11-06

## 状況

GRPO は同じ問題への複数の回答を群の中で比べ、モデルの重みを更新する。hypharness は API のモデルを使い、重みを学習する GPU も外部の学習 API も使わない。群の比較の代わりに独立した G 回の実行を行うと、費用が G 倍になり、DeLM の共有文脈を持たない分だけ本番の質が下がる。DeLM の共有文脈の失敗の項目には、どのやり方がどの条件で駄目だったかが根拠付きで残り、群の比較より細かい材料になる。

## 決定

- 重みは更新しない。群は作らない。
- 解答役は、1つの課題につき DeLM を1回動かす。
- オンラインでは、その実行の共有文脈から経験の一覧（対象のリポジトリごとのテキスト）を更新し、解答役のプロンプトに入れる。材料は、根拠に実行の結果を持つ失敗の項目と、報酬が 1 だった実行の事実の項目に限る。
- オフラインでは、課題をまたいだ結果で、方針役・分解役・解答役のコードとプロンプトを改良する。

## 結果

- 経験の一覧の更新はテキストだけで、ビルドを壊さないため門番が要らない。
- 共有文脈の項目はエージェント自身の判断で書かれるため、実行の結果と報酬で裏付けた項目だけを使う。
- コードとプロンプトの改良には、採否の信号が別に要る（ADR 0006）。
