# 0034 AgentDiet で縮める範囲を決め、ACON で縮め方を決める

日付: 2026-11-06

## 状況

文脈ファイルをモデルが自分で書き換えられるようにしても（ADR 0033）、解答役は数百ステップの履歴を持つ。モデルが毎回すべてを読み直して縮めるのは費用がかかる。AgentDiet（arXiv:2509.23586）は、外部のモデルが過去のステップの無駄・重複・期限切れを削る。ACON（arXiv:2510.00615、ICML 2026）は、圧縮の指針を自然文で持ち、失敗から指針を直す。中継が呼べるモデルは DeepInfra の DeepSeek V4.1 Flash だけ（`server/model.ts`）。

## 決定

- 文脈ファイルを唯一の正とする。モデルの `edit_context` と AgentDiet の置き換えは、どちらも同じ文脈ファイルを書き換える。
- AgentDiet が「いつ・どこを」決める。解答役の各ステップの後に、a=2 ステップ前の内容を、b=3 ステップ分の前後を渡して圧縮用のモデルで縮める。500 トークン未満のステップは圧縮せず、削減が 500 トークン未満なら元のままにする。
- 残すもの: エラーメッセージとトレースバックの全文、最後のテスト結果の要約行、ツールの呼び出しとそのステップの結論。
- 圧縮した結果は元のステップと置き換える。履歴から消さない。
- ACON が「どう縮めるか」を決める。圧縮の指針を `~/.hyph/acon/guidelines.md` に自然文で持ち、圧縮用のモデル呼び出しのシステムプロンプトに入れる。
- 指針はオフライン層で更新する。同じ課題で元の文脈では成功し、圧縮した文脈では失敗した実行の組を集め、失敗の原因を分析するモデル呼び出し1回で書き換える。
- 圧縮用のモデルは、中継が使う DeepSeek V4.1 Flash と同じにする。2つ目のモデルは足さない。
- 圧縮用のモデルの呼び出しの費用は、解答役の費用の上限に含める。
- モデルの重みは更新しない。小さいモデルへの蒸留はしない（ADR 0004）。

## 結果

- モデルが縮める前に、外部の圧縮が古いステップを縮めるため、モデルの編集の回数が減る。
- 圧縮の失敗（残すべき情報を削る）は、ACON の指針の更新で直す。直るまで報酬が下がる。
- 圧縮の費用が解答役の上限に入るため、圧縮で節約した分と圧縮の費用を同じ財布で比べられる。
- 圧縮用に安いモデルを呼ぶ場合に比べ、1回あたりの費用は高い。圧縮の入力は前後数ステップと短いため、差は小さい。
