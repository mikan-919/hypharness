# 0041 自己改良の1周は、流れの完了の後に固定部が回し、通った候補を統合ブランチに積む

日付: 2026-11-07

## 状況

ADR 0036 の自己改良の1周は、`bun run evolve` という別の命令で回す形になっていた。ADR 0002 は旧実装の `evolve` などの命令を引き継がないと決めている。また、1周で採用した候補はアーカイブに残るだけで、ハーネスは変わらなかった。

## 決定

- `bun run evolve` の命令はやめる。1周の仕組み（`server/evolve/`）は残す。
- 分解役が最終目的を満たしたと判断して流れが終わったら、固定部が hypharness 自身の改良の対象を1周改良する。回している間は開始の合図を受け付けない。
- 候補ごとに、統合ブランチの先端から一時的な作業ツリーを作り、解答役に変更を実装させ、検査に通ったら統合ブランチに比較して上書き（CAS）で積む。積んだ候補は、次に動くエージェントから効く（ADR 0022）。
- 周の間に流れが統合ブランチを進めていたら、その候補は積まずに 0 にする。
- モデルは中継を通して呼び、費用を `evolve-<時刻>` の課題として数える。

## 結果

- 採用の条件は検査に通ることだけなので、効果のない変更や悪くなる変更も積まれうる。悪くなった変更は ADR 0015 の取り消しの条件で外す。
- 積んだ候補は統合ブランチに入っているので、次の周の出発点にしても差分を当て直さない。アーカイブの系統は統合ブランチの1本になる。
