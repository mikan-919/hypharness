# 0013 ハーネスは統合ブランチに積み上げ、利用者が見られるようにする

日付: 2026-11-06

## 状況

ハーネスは常に動き続け、PR をマージするのは利用者である。前の課題の PR のマージを待つと、利用者がハーネスの律速になる。常に既定のブランチから始めると、分解役は前の課題に依存しない課題しか作れない。

## 決定

- ハーネスは対象のリポジトリに自分の統合ブランチを持つ。報酬が 1 になった解答は、課題ごとに1コミットとして統合ブランチに取り込み、次の課題はそこから始める。
- 利用者は、好きなときに統合ブランチを既定のブランチへマージする。
- 統合ブランチを origin に push し、利用者は既定のブランチへのマージを GitHub の PR で行う。
- ローカルの Web 画面には、課題ごとのコミット・差分・課題文・方針・共有文脈の失敗の項目を並べる。
- 分解役は、統合ブランチの今の状態を読んで、課題を1つずつ作る。

## 結果

- オフラインの遅れて取れる信号は、課題ごとのコミットを単位に、既定のブランチまで届いたか、届いた後に書き直されたかで取る。
- 利用者がある課題を拒否すると、その上に積んだ課題も巻き添えになる。統合ブランチは拒否された課題の手前まで戻し、拒否を最終目的の詰め直しのきっかけにする。
