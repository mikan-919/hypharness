# 0016 対話の画面を最初に作る

日付: 2026-11-06

## 状況

利用者が最初にハーネスに触れるのは、最終目的を詰める対話である（ADR 0003）。画面に並べるものを決めると、固定部とハーネスの間で受け渡すデータの形が先に決まる。

## 決定

- 最初に対話の画面を作る。裏の仕組みができるまでは、決めたデータの形に合う見本のデータで表示する。
- 画面の構成と状態の見せ方は、Grok Bot を参考にする。名前・ロゴ・配色・アバターの絵は使わない。
  - スレッド1本を論点エージェント1つに対応させる。
  - 論点エージェントの状態（調査中、質問待ち、開始のツールを呼んだ、詰まり）を示す。
  - 質問と推奨、選択肢、ADR の下書き、共有文脈の項目を、構造化された部品で示す。
- 質問の待ち行列の先頭を目立たせる。利用者は他のスレッドにも書き込めるが、その答えは、依存する論点の決定が出るまで論点エージェントが保留にする。
- エージェント全体のトークンの使用数を示し、ストリーミング中のトークン数をリアルタイムで更新する。
- 開始の合図のボタンと、開始のツールを呼んだ論点エージェントの数を示す。
- 画面はハーネスに置き、改良の対象とする。会話の内容はハーネスから受け取る。
- トークン数と費用は、固定部の中継が SSE で直接画面に配信する。ハーネスを経由させない。中継は呼び出しごとに論点エージェントと課題の印を受け取り、全体の合計、論点エージェントごと・課題ごとの数、入力・出力・キャッシュから読んだ分の内訳、費用を記録する。
