# 0035 文脈管理を5つの仕組みで組む

日付: 2026-11-06

状態: 一部を ADR 0031 で置き換えた。4ターンごとの要約、システムプロンプトのブロックの行、要約ノードの選抜をやめ、10万トークンのしきい値で縮める形にした。

## 状況

ハーネスのエージェントは、会話を追記だけのメッセージ列として持ち、長い課題で文脈が伸び続ける。文脈管理の方式は1つにまとまらない。参照した文献の分担は次のとおり。

- LCM（arXiv:2605.04050）: 元のメッセージを SQLite に残し、古い部分を階層の要約ノードにまとめる。想起のツールを持つ。
- CLM（arXiv:2609.37725）: 文脈をファイルとしてモデルに編集させる。
- VISTA（arXiv:2606.30005）: 文脈のブロックごとのトークン数・新しさ・参照履歴・残り予算を見せる。
- TokenPilot（arXiv:2606.17016）: 取り込み時に縮め、先頭を安定させてプロンプトキャッシュを保つ。
- ReCAP（arXiv:2609.40118）: 重要度と依存リンクを保存し、要約の選抜に使う。注意の重みは API から取れない。

## 決定

- 正は SQLite（`~/.hyph/ctx/<id>.sqlite`）に追記だけで保存する元のメッセージ。`recall` ツール（`query`・`max_results`）で全文を取り戻せる。
- 毎ターン、文脈ファイル（`~/.hyph/ctx/<id>.md`）を「直近の生メッセージ + 選んだ要約ノード」で組み立て、モデルは `edit_context`（`old`・`new`）で書き換える。`old` は1回だけ現れるとき置換し、0回・2回以上は変えず理由を返す。空にする編集は断る。
- 編集は要約ノードの差し替えとして保存し、元のメッセージは残す。システムプロンプトと最初の課題文はファイルの外に固定する。
- システムプロンプトに、ブロックごとの id・種別・トークン数・最終参照からのターン数・参照回数・残り予算を1行ずつ入れる。
- ツール結果は文脈に入れる前に、決まった規則（連続する同じ行の圧縮、空行の圧縮、10,000 文字で切る）で縮める。モデルは呼ばない。先頭は変えず、新しい内容は末尾に足す。要約は4ターンごとにまとめて作る。
- 要約ノードは、現在のリクエストとの語の一致と依存リンクで選ぶ。注意の重みは使わない。参照回数と依存リンクで代用する。
- 文脈ファイルが `contextWindow` の 70% を超えたら、`edit_context` と `recall` の結果に要約を求める指示を添える。
- 圧縮の指針（ACON）と AgentDiet の設定（ADR 0034）は、この文脈管理の上で動かす。

## 結果

- 文脈の大きさをモデルとハーネスの両方が制御する。モデルは `edit_context` で、ハーネスは4ターンごとの要約と取り込み時の圧縮で縮める。
- SQLite・Markdown・要約ノードの3つを同期させる処理が必要になる。再起動時の整合を取る処理を要する。
- 取り込み時の圧縮規則は決定的なので、テストで再現できる。モデルの呼び出しは要約のときだけになる。
