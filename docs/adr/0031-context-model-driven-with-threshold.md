# 0031 作業文脈は、モデルの編集としきい値のときだけ作り直す

日付: 2026-11-07

## 状況

最終目的の 5 で、CLM（モデルが自分の作業文脈を編集する）と LCM（原文を残し、要約から引き直す）を入れた。最初の実装には次の問題があった。

- 毎回のモデルの呼び出しで、システムプロンプトの末尾にブロックごとの状態の行（最後の参照からのターン数、参照回数）を付け直していた。会話の先頭が毎回変わり、プロンプトのキャッシュが外れていた。
- 文脈ファイルを作業ツリーの外に書いていたが、モデルに渡す会話は全文のままで、文脈は短くなっていなかった。
- 4ターンごとに要約を作っていた。いつ縮めるかをハーネスが決めるため、モデルが文脈を編集する CLM の意味がなかった。
- 記録を役割ごとに1つにし、全課題をまたいで増やしていた。論点エージェントの `edit_context` は処理がなく、呼ぶと誤りになっていた。

## 決定

- CLM: `edit_context` は、ここまでの会話をモデルが書いた作業文脈に置き換える。次の呼び出しから、置き換えた会話の代わりに作業文脈を渡す。論点エージェント・分解役・解答役のすべてに渡す。
- LCM: 原文は会話の記録に残し、`recall` で引ける。モデルが縮めないまま、モデルに渡した文脈が `compactAtTokens`（10万トークン）を超えたときだけ、決まった手順で古い会話を要約に置き換える。ターンの数では縮めない。
- モデルに渡す会話を作り直すのは、この2つのときだけにする。その間は会話の先頭を変えず、キャッシュを効かせる。
- 作業文脈は、課題の作業ツリーごと（論点エージェントはリポジトリと論点ごと）に分ける。
- しきい値の半分を超えたら、ツールの結果に文脈の大きさを書き添え、縮めるかをモデルに判断させる。

## 結果

- 要約ノードの重要度の並べ替え（依存・参照回数）は、文脈ファイルに入れる要約を選ぶためのものだったので外した。何を残すかはモデルが `edit_context` で決める。
- しきい値の値は、課題ごとの入力のトークン数とキャッシュの割合を見て調整する。
