# 0040 保存の応答の版を画面の正にする

日付: 2026-11-06

## 状況

`routes/page.tsx` の `send` は、保存の版に `goalVersion()`（`/api/dialog` の SSE で届いた版）を使い、保存の応答の版を使っていない。409 の後「このまま上書きする」も同じ古い版を送るため、また 409 になる。保存ボタンの `disabled` は `dirty` と `sending` で決まり、`dirty` は SSE の `goal.text` と入力中の本文の比較で決まる。SSE が届くまで編集し直しても保存できない場合がある。

## 決定

- 保存の応答（200 と 409 の両方）から `text` と `version` を取り、画面の `savedText`・`savedVersion` を更新する。
- 保存ボタンは、`sending` か `draft === savedText` のときだけ押せなくする。SSE は `savedText` の更新に使わない。
- 409 の「最新を読み込む」は `savedText` を表示し、「このまま上書きする」は `savedVersion` で送る。
- Monaco のエディタでも同じにする。エディタの内容が `savedText` と違えば保存できる。
- SSE は、他の書き手の書き換えを表示に映すためだけに使う。

## 結果

- 保存の直後に本文を変えると、SSE を待たずに保存できる。
- 409 の後「このまま上書きする」で保存が通り、版が進む。
- 画面が持つ版が2つ（`savedVersion` と SSE の版）になるため、表示する版と保存に使う版を分けて扱う必要がある。
