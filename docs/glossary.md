# 用語集

- 最終目的: 利用者が作りたいもの。利用者とハーネスの対話で鋭くしていく。
- 分解役: 最終目的を課題文に分けるエージェント。統合ブランチの今の状態を読み、課題を1つずつ作る。
- 統合ブランチ: ハーネスが対象のリポジトリに持つブランチ。報酬が 1 になった解答を課題ごとに1コミットとして積み、origin に push する。利用者が既定のブランチへマージする。
- 課題文: 最終目的に向けて実際にやる仕事1つ分の文章。分解役が書く。評価のためだけの使い捨ての課題は作らない。
- 方針: 課題文から、変える振る舞い・受け入れの条件・外から見える名前や書式・やらないことを決めたもの。各項目は課題文かリポジトリからの引用を根拠に持つか、方針役が決めたと印を付ける。「やらないこと」を必ず含む。解答役に渡す。
- 方針役: 課題文から方針を作るエージェント。DeLM（中央の調整役を置かず、検証済みの共有文脈とタスクの待ち行列で複数のエージェントが分担する方式。arXiv 2606.10662）で、複数のエージェントが案と反論を共有文脈に書き、1つの方針に収束させる。
- 検証生成役: 方針から、元の状態のリポジトリで正しい理由で失敗するテストを書くエージェント。
- 解答役: 課題を解くエージェント。DeLM で動かし、1つの課題につき1回実行する。API のモデルを使い、重みは更新しない。
- 共有文脈: DeLM のエージェントが読み書きする追記だけの記録。項目は事実・失敗・完了の要約の3種類で、書いた後は変えない。
- 報酬: 既存の検査と、検証生成役のテストをすべて通れば 1、そうでなければ 0。
- 経験の一覧: 解答役の共有文脈から、何が効き何が効かなかったかをまとめたテキスト。対象のリポジトリごとに持ち、解答役のプロンプトに入れる。根拠に実行の結果を持つ失敗の項目と、報酬が 1 だった実行の事実の項目だけを材料にする。
- オンライン: 1つの課題の中で働く層。方針役のブレインストーミングと、経験の一覧の更新を行う。
- オフライン: 課題をまたいで、ハーネスのコードとプロンプトを改良する層。
- 固定部: 既定のブランチの版でホストとして動く最小の部分。モデルの呼び出しの中継、隔離環境の起動、統合ブランチへの push、遅れて取れる信号の集計、採否と取り消しの判定だけを持つ。それ以外のハーネスの中身はすべて改良の対象で、隔離環境で動く。
- 作業文脈: モデルが `edit_context` で書いた、それまでの会話の代わり。次の呼び出しから、置き換えた会話の代わりにモデルへ渡す。モデルが縮めないまま文脈が 10万トークンを超えたときは、ハーネスが決まった手順で古い会話の要約を足す（ADR 0031）。課題の作業ツリーごとに分ける。
- 原文: 作業文脈に置き換えた会話の元のメッセージ。消さずに会話（論点エージェントは対話の記録）に残す。
- 想起: `recall` ツール。`query` と `max_results` を受け取り、作業文脈に置き換えた会話の原文から一致するものを返す。
- 圧縮の指針: 文脈を縮めるときに残すもの・捨てるものを自然文で書いた `harness/settings.ts` の `COMPRESSION_GUIDE`。`edit_context` の説明に入る。自己改良の変更の対象。
- 反射モジュール: AgentDiet で、解答役の各ステップの後に a ステップ前の内容を縮める、圧縮用のモデル呼び出し。エラー全文・最後のテスト結果の要約行・ツールの呼び出し・結論は残す。
- 自己改良の1周: 弱点発見・提案・回帰テスト・採用・アーカイブを順に行う、オフライン層の単位。`bun run evolve` で回す。
- 進化のアーカイブ: `~/.hyph/evo/archive/` に置く、採用したハーネスの候補。次の周はここから1つ選んで出発点にする。

旧実装の設計書では、オンライン RSI を「実行中のエージェントが自分の方針を直すもの」、オフライン RSI を「ハーネス全体の版を作り直すもの」としていた。この用語集の定義はそれと異なる。

対話の層の構成:

- 論点エージェント: 最終目的を詰める対話で、1つの論点を受け持つ DeLM のエージェント。調査から推奨までを行い、他の論点の決定は共有文脈から読む。
- サブエージェント: 論点エージェントが役割（コードの調査、文献の調査、文書の記録など）ごとに呼び出すエージェント。役割での分担はここで行い、DeLM の層では行わない。
- 質問の待ち行列: 論点エージェントが利用者に出す質問を並べる場所。利用者には1度に1問を出し、依存の少ない論点の質問を先に出す。
