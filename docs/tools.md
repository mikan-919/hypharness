# ツール一覧

エージェントがモデル呼び出しの中で使えるツールの一覧です。定義は [`src/tools.ts`](../src/tools.ts) にあり、説明文と引数はそこからモデルに渡されます。引数名の `?` は省略できる引数を表します。

すべてのツール呼び出しは、エピソード（1体のエージェントが1つのタスクを処理する一連のやり取り）と呼び出し ID の組で結果を記録します。プロセスが途中で止まって再開したとき、記録済みの呼び出しは再実行せず、記録した結果を返します。データベースだけを変えるツールは、変更と記録を同じトランザクションで確定します。ツールの出力は `toolOutputLimit`（既定値 4000 文字）で切り詰められます。

## 文脈（CLM）

各エージェントの文脈は、タスクをまたいで残る作業記憶と、実行中のタスクの会話（live context）からなります。自分の文脈だけを編集でき、他者の文脈は読むだけです。作業記憶は全体の置き換えと一部の置き換え、実行中の文脈は範囲を指定した要約への置き換えができます。毎回のツール結果の末尾には、そのメッセージの番号と実行中の文脈の大きさ（`[#N · live context: ~X tokens]`）が付きます。

| ツール | 引数 | 働き |
| --- | --- | --- |
| `memory_write` | `content` | 自分の作業記憶を置き換える。上限は `memoryLimit`（既定値 6000 文字）で、超えると拒否される。旧版は履歴に残る |
| `memory_edit` | `old`, `new` | 自分の作業記憶のうち、1か所だけに現れる文字列を置き換える（`new` を空にすると削除）。全文を書き直さずに一部を直せる。上限と版の履歴は `memory_write` と同じ |
| `memory_restore` | `version` | 自分の作業記憶を以前の版に戻す。戻す前の版も履歴に残る |
| `context_read` | `agent?`, `part`, `version?`, `offset?`, `limit?` | 自分または他者の作業記憶（`part: memory`、版の指定可）か実行中の文脈（`part: live`）の一部を読む。既定で 2000 文字、最大 4000 文字 |
| `context_outline` | なし | 自分の実行中の文脈を、番号・役割・大きさの一覧で見る |
| `context_edit` | `from`, `to`, `note` | 自分の実行中の文脈の `from`〜`to` 番のメッセージを短い注記に置き換える。注記が置き換える範囲より短くないと拒否される。次の生成から反映され、元の内容は `episode_history` に残る |
| `news` | なし | 前回確認してから他のエージェントが行ったこと（知識の公開、タスクの完了や返却、検証結果、組織の変更）を最大40件、要約だけで返す |

## 目標

最上位目標 G0 は目的そのもので、内容の変更、破棄、移譲はできません。

| ツール | 引数 | 働き |
| --- | --- | --- |
| `goal_list` | なし | 目標を所有者・状態・版（`rev`）付きで一覧する |
| `goal_create` | `parent`, `description` | 開いている目標の下に下位目標を作る。作った本人が所有者になる |
| `goal_update` | `id`, `rev`, `description?`, `drop?` | 自分が所有する目標の説明を直すか、破棄する（未着手のタスクは失敗扱いになる）。`rev` が現在の版と違うと競合として拒否される |
| `goal_transfer` | `id`, `to` | 自分が所有する目標を他のエージェントに引き渡す |
| `goal_complete` | `id`, `deliverable` | 自分が所有する目標を達成として提出する。下位目標がすべて閉じ、待ちのタスクがないことが条件。提出者以外の検証で合格すると完了になる |

## タスク

| ツール | 引数 | 働き |
| --- | --- | --- |
| `task_list` | `goal?`, `status?` | タスクを新しい順に最大40件一覧する |
| `task_get` | `id` | タスクの結果、差し戻し理由、検証者を読む |
| `task_create` | `goal`, `description`, `assignee?` | 開いている目標の下に作業タスクを作る。担当を指定しなければ誰でも取得できる。休眠中のエージェントを担当にすると起こす |
| `task_assign` | `id`, `to` | 自分が作った未着手のタスクを別のエージェントに付け替える（`null` で誰でも可） |
| `task_finish` | `result`, `verdict?` | 現在のタスクを終える。作業タスクは結果と成果物の場所を書き、別のエージェントの検証待ちになる。検証タスクは `verdict` に `pass` か `fail` と根拠を書く。待ち作業のない目標の steer タスクは、目標を提出・分割・修正しない限り終えられない |
| `task_release` | `note` | 現在のタスクを未完了のまま返し、次に取る人への注記を残す |

## 知識

知識は Gist（1行）、Summary（短い説明）、Raw（原資料）の3段と出典を持ち、登録時は未検証の仮説です。

| ツール | 引数 | 働き |
| --- | --- | --- |
| `knowledge_add` | `gist`, `summary`, `raw`, `source`, `domain?` | 知識を出典付きで登録する。領域を指定するとその領域に結び付ける |
| `knowledge_search` | `query`, `domain?`, `status?` | 知識を検索し、Gist だけを返す |
| `knowledge_get` | `id`, `level` | 知識を Summary または Raw まで展開する |
| `knowledge_verify` | `id` | 仮説の検証を別のエージェントに依頼する。結果は verified か rejected になる |

## 担当領域（domain）

領域は知識への参照だけを持ちます。分割・統合・移譲をしても知識本体は複製も削除もされません。領域を変更できるのは管理者（steward）だけです。

| ツール | 引数 | 働き |
| --- | --- | --- |
| `domain_list` | なし | 領域を管理者・状態・知識の件数付きで一覧する |
| `domain_create` | `name`, `description` | 領域を作る。作った本人が管理者になる |
| `domain_link` | `domain`, `knowledge` | 既存の知識を自分が管理する領域に結び付ける。1つの知識は複数の領域に属せる |
| `domain_split` | `id`, `parts` | 自分が管理する領域を、知識の参照を分け持つ下位領域に分割する。元の領域は退役し、参照は履歴として残る |
| `domain_merge` | `ids`, `name`, `description` | 自分が管理する複数の領域を、すべての参照を持つ新しい領域に統合する。元の領域は退役する |
| `domain_transfer` | `id`, `to` | 領域の管理を他のエージェントに引き渡す |

## 組織

エージェントの生成と休眠は dynamic モードでだけ使えます。single と fixed では構成が固定されます。

| ツール | 引数 | 働き |
| --- | --- | --- |
| `agent_list` | なし | エージェントを役割・状態・負荷（取得中と割り当て済みのタスク数）付きで一覧する |
| `agent_spawn` | `id`, `role`, `reason` | 新しいエージェントを作る。上限 `maxAgents` に達していると拒否される。理由はログに残る |
| `agent_sleep` | `id`, `reason` | 自分が作ったエージェントか自分自身を休眠させる。文脈は残り、タスクを割り当てると起きる。lead は休眠できない |

## 作業ディレクトリと外部

ファイル操作は作業ディレクトリ（`<--dir>/workspace`）の中に限られ、外を指すパスはシンボリックリンク経由も含めて拒否されます。

| ツール | 引数 | 働き |
| --- | --- | --- |
| `file_list` | `path?` | ディレクトリ以下のファイルを最大200件一覧する |
| `file_read` | `path`, `offset?`, `limit?` | ファイルの一部を読む。既定で 3000 文字、最大 4000 文字 |
| `file_search` | `query`, `path?` | 文字列を含む行を大文字小文字を区別せずに探し、ファイル名と行番号付きで最大40件返す |
| `file_write` | `path`, `content` | ファイルを書く。途中のディレクトリは作られる |
| `shell` | `command` | bubblewrap 内の作業ディレクトリでシェルコマンドを実行する（60秒で打ち切り）。起動時に `--allow-shell` を指定し、bubblewrap がある場合だけ使える |
| `web_search` | `objective`, `queries`, `max_results?`, `include_domains?`, `after_date?` | Parallel Search API に fast モードで検索を送り、関連順の URL と抜粋を返す（既定で8件）。各結果は、題名を要旨、抜粋を原資料、URL を出典とする未検証の知識として自動で登録され、結果に知識 ID が付く。同じ URL は1件だけ登録される。環境変数 `PARALLEL_API_KEY` がない起動では、モデルに渡す一覧から外れる |

## MCP のツール

状態ファイルと同じディレクトリに `mcp.json` を置くと、外部の MCP サーバー（ツールを提供するプロセスまたは HTTP サーバー）を起動時に接続します。設定例は [README](../README.md#mcp-サーバー) にあります。`mcpServers` の各名前に、標準入出力なら `command`・`args`・`env`、HTTP なら `type: http`・`url`・`headers`・`oauth` を指定します。`oauth: true` のサーバーは `mcp-login` で保存した `mcp-auth.json` のトークンで接続します。ファイルがない場合は追加されません。

サーバーが提供する説明と入力スキーマをそのまま使い、各ツールを `mcp__サーバー名__ツール名` として提供します。標準入出力のサーバーはシェルと同じ隔離環境で起動し、環境変数は `env` に指定したものだけを渡します。bubblewrap がない場合は起動できません。HTTP の接続先は指定された URL をそのまま使います。

成功した結果の全文は、出典 `mcp:サーバー名/ツール名` の未検証知識として保存します。モデルには既存の出力上限で切った結果を返します。接続に失敗したサーバーはログに理由を出して除き、切断されたサーバーは次の呼び出し前に再接続します。
