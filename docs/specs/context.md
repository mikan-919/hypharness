# context

文脈管理が受け持つ振る舞い。

- 会話を `~/.hyph/ctx/<エージェントの id>.sqlite` に追記だけで保存し、元のメッセージを消さない。
- メッセージ間の依存（ツールの結果と、その呼び出しを含むアシスタントのメッセージ）を保存する。
- 4ターンごとに、直近より前のメッセージをまとめた要約ノードを作る。要約ノードは元のメッセージの id を持つ。
- 毎ターン、`~/.hyph/ctx/<エージェントの id>.md` を組み立て、直近の生メッセージと選んだ要約ノードを並べる。
- 要約ノードは、現在のリクエストの語の一致と依存でつながるブロックを優先して並べる。
- `recall` で SQLite を検索し、一致したメッセージの全文と要約ノードの id を返す。
- `edit_context` で `old` が1回だけ現れるとき、その1箇所を `new` に置き換え、要約ノードの差し替えとして保存する。0回・2回以上・空にする編集は変えずに理由を返す。
- システムプロンプトに、ブロックごとの id・種別・トークン数・最後の参照からのターン数・参照回数・残り予算の1行を入れる。
- 文脈のトークン数が `contextWindow` の 70% を超えたら、`recall` と `edit_context` の結果に縮める指示の1行を添える。

コード: `harness/ctx.ts` の全体（`ctx`・`blocks`・`summarizeOld`・`buildContextFile`・`editContext`・`contextStatus`・`search`・`dependenciesOf`・`overLimit`）と、`harness/agent.ts` の `recall` と `runAgent` の中でシステムプロンプトに文脈の行を足す箇所。
