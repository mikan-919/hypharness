# 仕組み

hypharness は「DeLM × CLM Core Specification」に基づくエージェントハーネスです。組織全体で共有する目標・タスク・知識・担当領域を DeLM、各エージェントが持ち続ける文脈を CLM として分けて管理します。この文書では、状態の置き場所、スケジューラーの動き、検証、文脈の扱い、停止と再開を説明します。各ツールの引数は [ツール一覧](tools.md) を参照してください。

## 状態

1つのセッションは1つのディレクトリ（`--dir`、既定値 `.hyph`）で、次のものを持ちます。

| 場所 | 内容 |
| --- | --- |
| `state.sqlite` | すべての状態。WAL モード（書き込み中でも読み取りを妨げない SQLite の記録方式）で開く |
| `workspace/` | 成果物。ファイル系ツールと `shell` の作業場所 |
| `contexts/<agent>.md` | 各エージェントの作業記憶と実行中の文脈の写し。人が読むためのもので、ハーネスは読まない |
| `run.log` | ダッシュボードから起動した実行の出力 |

`state.sqlite` の主な表は次のとおりです。

| 表 | 内容 |
| --- | --- |
| `meta` | 目的、制約、設定、モデル呼び出しの累計、各エージェントの `news` の既読位置 |
| `agents` | エージェントの役割、状態（active / dormant）、生成元 |
| `goals` | 目標の木。所有者、状態（open / review / done / dropped）、提出物、差し戻し理由、検証者、版 |
| `tasks` | タスク。種類（work / verify / steer）、担当、取得者と取得期限、結果、検証者、版 |
| `knowledge`, `domains`, `domain_knowledge` | 知識（Gist / Summary / Raw と出典、検証状態）と担当領域、その対応 |
| `context`, `context_history` | 作業記憶の現在の版と過去の版 |
| `episodes`, `episode_history` | エピソードの会話と、`context_edit` で置き換える前の会話 |
| `ops` | ツール呼び出しの結果の記録（再開時の重複防止） |
| `usage` | モデル呼び出しごとのトークン数、入力文字数、待ち時間 |
| `log` | イベントログ。`news` とダッシュボードの元になる |

目的は最初の起動時に固定されます。別の目的で同じディレクトリを開くと `This store already has a different purpose` で止まります。

## 組織の形

| モード | 初期構成 | 生成・休眠 | 同時実行 |
| --- | --- | --- | --- |
| `single` | lead のみ | なし | 1 |
| `fixed` | lead、worker、reviewer | なし | 設定値まで |
| `dynamic` | lead のみ | エージェントが `agent_spawn` と `agent_sleep` で判断する。ホストも、検証者がいないとき `verifier` を作り、仕事のない巡回が `idleRounds`（既定値 3）続いたエージェントを休眠させる | 設定値まで |

設定の既定値は [`src/db.ts`](../src/db.ts) の `defaultConfig` にあります。エージェント数、同時実行数、モデル呼び出し回数、スケジューラーの巡回回数には上限がありません（fixed のエージェント数は3、single は1）。上限なしの値は JSON に `null` として保存され、読み込み時に上限なしに戻ります。文脈の大きさを決める値は上限を持ち、1タスクの手数 16、作業記憶 6000 文字、ツール出力 4000 文字です。タスクの取得期限は 10 分です。

## 実行の循環

スケジューラーは巡回（round）を繰り返します。1回の巡回の流れは次のとおりです。

1. 期限切れの取得を解放し、待ち作業のない開いた目標ごとに、その所有者へ steer タスク（次の手を決めるタスク）を作る。最初の作業も、この規則で lead に割り当てられる。
2. G0 が完了していれば `done`、呼び出しの累計が上限に達していれば `budget` で終わる。
3. 稼働中のエージェントごとに、再開すべきエピソードか取得できるタスクを選ぶ。検証タスクを優先し、提出者本人は自分の提出物の検証を取れない。同時実行の上限まで集める。
4. 集めたエピソードを並行に実行し、全員が終わるのを待つ。

エピソードの中では、エージェントが目的・観察・計画・実行・検証・学習の循環を自分で回します。システムプロンプトは目的・制約・役割・規則だけからなり、時刻や件数を含みません。最初のメッセージは作業記憶、タスクの説明、目標の連なり、未読のイベント数だけです。

steer タスクを受けた所有者は、自分で作業する、タスクや下位目標を作る、目標を修正・破棄する、`goal_complete` で提出する、のいずれかを選びます。待ち作業のない目標の steer タスクを、何もせずに終えることはできません。

## 検証

作業タスクの完了（`task_finish`）と目標の提出（`goal_complete`）は、提出者を除外した検証タスクを生みます。合格すると完了し、不合格なら理由を付けて差し戻されます。

- dynamic で検証を取れる稼働中のエージェントがいないときは、休眠中のエージェントを起こすか、`verifier` を作ります。
- single では他者がいないため自己検証になり、`verified_by` に本人が記録されます。
- 知識は登録時は仮説で、`knowledge_verify` の依頼を別のエージェントが検証して verified か rejected になります。`web_search` の結果は、ホストが出典 URL ごとに1件の仮説として自動で登録します。

## 文脈（CLM）

- **作業記憶**: タスクをまたいで残る唯一の文脈です。`memory_write` で丸ごと、`memory_edit` で一部だけ書き換えます。上限を超えると拒否されます。旧版は `context_history` に残り、`memory_restore` で戻せます。
- **実行中の文脈**: エピソードの会話です。各手番の後に保存されます。毎回のツール結果の末尾には、そのメッセージの番号と文脈の大きさ（`[#4 · live context: ~12000 tokens]`）が付き、3万2千トークンを超えると圧縮を促す一文が加わります。大きさは、そのツールを呼んだモデル呼び出しについて提供元が報告したトークン数に、結果の長さを4文字1トークンとして足した推定値です。保存したメッセージの文字数は、暗号化された推論データを含むため、トークン数の数倍になり、目安に使えません。エージェントは `context_edit` で、あるツール呼び出しから後の回答までの範囲を要約1つに置き換えられます。CLM の参照実装（facebookresearch/context-language-models）と同じく、要約が置き換える範囲より短くない編集は拒否します。参照実装と違い、ツール呼び出しと結果の対応は編集後も保たれます。置き換え前の会話は `episode_history` に残ります。
- **他者の文脈**: `context_read` で一部を読めますが、編集はできません。
- **他者の変更**: 自動では入力に挿入しません。`news` で前回の確認以降のイベントを要約で取得します。

1タスクの手数とツール出力の長さに上限があるため、作業全体の量が増えても1回の入力は一定の範囲に収まります。ただし上限は手数あたりの出力に対するもので、1エピソード内の入力は手数とともに増えます。大きな出力は `context_edit` で畳むことを想定しています。

## 停止と再開

- **取得**: タスクの取得は条件付き更新で、1体だけが成功します。取得には期限（lease）があり、期限が切れたタスクは再び取得可能になります。
- **重複防止**: ツール呼び出しは (エピソード, 呼び出し ID) ごとに結果を `ops` に記録します。再開時、記録済みの呼び出しは再実行しません。
- **再開**: 起動時には、前のプロセスが残した取得を引き継ぎ、実行中だったエピソードを続きから再開します。
- **時間切れ**: モデル呼び出しは `MODEL_TIMEOUT_MS`（既定値 300000 ミリ秒）で打ち切り、モデルエラーとして扱います。
- **エラー**: 同じタスクで3回続けてモデルエラーが起きると、タスクを手放します。すべてのエピソードが失敗する巡回が3回続くと（利用上限や認証の失敗など）、予算を使い切る前に `error` で止まります。

ホストは1プロセスで動かす前提です。同じディレクトリを複数のプロセスで同時に開くと、実行中エピソードの再開が衝突します。

## 終了状態

実行の最後に出る JSON の `status` は次のいずれかです。

| 値 | 意味 |
| --- | --- |
| `done` | G0 が検証を通って完了した |
| `budget` | モデル呼び出しの累計が `--calls` に達した。上限を上げて再開すると続く |
| `stalled` | 稼働中のエージェントに取れるタスクがなく、検証の手配もできない |
| `error` | すべてのエピソードが失敗する巡回が3回続いた |
| `rounds` | 巡回数が `--rounds` に達した。`status` コマンドの表示でもこの値になる |

同じ JSON には、モデル呼び出し数、入出力とキャッシュのトークン数、最大入力文字数、エージェント数、完了した作業タスク数、組織の変更数（生成、休眠、起床、目標と領域の移譲、領域の分割と統合）が入ります。`--check` を指定した場合は、検査コマンドの終了コードが `checkExit` に入ります。
