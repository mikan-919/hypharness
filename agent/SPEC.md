# エージェントの仕様

改善役は、`evolve` の改善対象が spec のとき、先にこの文書を直し、それに合わせてコードを直す。

## 入出力

- 入力: `/task.md` の課題文。`/work` が作業用ディレクトリ。モデルは `/model.sock` の中継だけで呼ぶ。
- 状態: `/state` は課題をまたいで残る（計測では試行ごとに空）。`memory.sqlite` が記憶、`last.json` が直前の課題で使った・作った記憶の番号、`outcome.json` がノードの書いたその課題の成否。
- 出力: `/work` の変更。成否は判定コマンドが決め、終了コードは使わない。

## 各部の責務と依存の順

1. 前の課題の評価（`memory.judge`）: `last.json` と `outcome.json` が揃っていれば、記憶の評価を成否で上下させ、下がりきった記憶を外す。
2. 文脈選択（`memory.entries`）: 課題文で記憶を検索し、参照関係と評価で並べ、上位5件を最初のメッセージに入れる。
3. 行動ループ（`act`）: モデルを呼び、`sh`・`expand`・`delegate` を実行する。`finish` かツールなしの応答で終える。
4. 原文保存（`memory.add`）: `sh` の出力と委任の結果は全文を残し、文脈には番号と先頭4,000文字だけを入れる。
5. 作業文脈（`compact`）: 入力が16,000トークンを超えたら、直近6件より古い出力を参照に置き換える。
6. 委任（`delegate`）: 親だけが使える。子は新しい文脈で20回まで呼び、要約を返す。
7. 振り返り（`remember`）: 作業の後に3回まで。記憶は原文からの引用が原文に含まれるときだけ残し、要旨がほぼ同じ記憶には統合する。

## 失敗の扱い

- モデルを呼べない（予算切れなど）・応答の失敗・呼び出しの上限（子と振り返りを含め60回）では、作業を止めて終える。
- ツールの失敗は例外の文をツールの結果として返し、モデルに直させる。
