# hypharness

hypharness は、利用者との会話を記憶し、目的に関係する仕事を進めるエージェントの実行基盤です。会話、記憶、目標と作業の状態を SQLite（ファイルに保存するデータベース）に置きます。

## 起動

Bun とモデル提供元の認証が必要です。初回は埋め込みモデルをダウンロードします。

```sh
bun install
bunx @earendil-works/pi-ai login openai
bun run src/index.ts serve
```

ブラウザーで `http://127.0.0.1:4321/` を開き、チャットで話します。入力欄の「目的に設定」は最上位目的を更新します。別の端末からも次の方法で設定できます。

```sh
bun run start '調査して報告書を作る'
```

既定の保存先は `.hyph/main/state.sqlite`、成果物の置き場所は `.hyph/main/workspace/` です。`serve --dir <ディレクトリ>` で保存先、`--port <番号>` で待ち受け先のポート、`--concurrency <数>` で同時に進める仕事の数を変えられます。同じ保存先で常駐プロセスを複数起動しないでください。

## 記憶と仕事

発言と応答は文ごとに保存されます。埋め込み（文章を意味の距離を測る数値に変換したもの）には `Xenova/multilingual-e5-small` を使います。直近6件は応答の文脈にも残り、それより前の記憶は市場の候補になります。市場は記憶の組み合わせを評価し、文字数に上限のある材料を応答モデルに渡します。モデルが必要な場合は知識の検索と取得もできます。

目的を変えても既存の下位目標は消えません。所有者に再検討の仕事が渡り、実行中のエピソード（1つの仕事を進めるモデルとのやり取り）は継続します。エピソードが終わった枠は次の仕事を取ります。成果は別の担当による検証を通った後に完了します。

記憶市場は資本と信用を記録し、利用者の反応を評価します。距離の分布から担当の再編候補を作り、担当の判断に基づいて分割や統合を進めます。現状の実装範囲と保存方法は [仕組み](docs/architecture.md) を参照してください。

## ツールと隔離

`web_fetch` は公開された HTTP(S) ページを取得し、出典付きの未検証知識として保存します。内部ネットワークへの接続と、そのアドレスへの転送は拒否します。`web_search` は `PARALLEL_API_KEY` を設定した場合に使えます。

`serve --allow-shell` は、bubblewrap（プロセスから見えるファイルを制限する仕組み）がある場合にシェルを許可します。シェルは作業領域に書き込め、ネットワークに接続できます。作業領域内の `.env` と `auth.json` の内容は隠されます。認証情報や状態を共有・コミットしないでください。

## MCP サーバー

MCP（外部のサーバーが提供するツールを呼び出すための通信方式）を使う場合は、常駐プロセスの起動前に `.hyph/main/mcp.json` を作ります。`--dir` を指定した場合は、そのディレクトリの `main/mcp.json` に置きます。

```json
{
  "mcpServers": {
    "local": {
      "command": "bun",
      "args": ["/workspace/server.js"],
      "env": { "SERVICE_NAME": "example" }
    },
    "remote": {
      "type": "http",
      "url": "http://127.0.0.1:8080/mcp",
      "headers": { "X-Example": "value" }
    }
  }
}
```

`command` のサーバーは標準入出力で接続し、シェルと同じ bubblewrap の中で起動します。サーバーの環境変数は `env` に書いた値だけです。`type: http` は指定された URL に接続し、プライベートアドレスも使えます。`headers` は接続時の HTTP ヘッダー（要求に付ける情報）です。設定には認証情報を含められるため、共有・コミットしないでください。

起動時にツールの一覧を取得します。設定ファイルがなければ MCP のツールは追加されません。接続できないサーバーは理由をログに記録して除き、ほかのサーバーは使えます。ツールの結果は未検証の知識として保存されます。設定の変更は次の起動から反映されます。測定用の保存先には設定ファイルを置きません。

## 比較と開発

比較実験の `bench`、LoCoMo、自己改善の `rsi` は、常駐用とは別の保存先を使います。測定の使い方は [LoCoMo](docs/locomo.md) を参照してください。

```sh
bun run bench 'ToDo 管理の CLI を作る' --calls 60
bun run rsi --generations 3
bun run check
bun test
```

テストは擬似のモデル提供元と埋め込みを使います。構成は [仕組み](docs/architecture.md)、開発時の指示は [AGENTS.md](AGENTS.md) にあります。
