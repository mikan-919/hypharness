# Hypharness

画面と中継を Cloudflare に置き、タスクを手元のノードで実行するハーネス。全体の設計と段階は [docs/architecture.md](docs/architecture.md) にある。

## 構成

| 場所     | 役割                                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `src/`   | Cloudflare Workers で動く画面と中継。パスキーでログインし、ノードのペアリング、タスクの待ち行列、実行権（期限45秒と世代番号）を持つ   |
| `node/`  | 手元で動くノード。中継に WebSocket で接続し、割り当てられたタスクのコマンドを bubblewrap の隔離環境で実行する。候補の計測もここで行う |
| `agent/` | 進化対象のエージェント。計測では、コミットから取り出したこのディレクトリを隔離環境に読み取り専用で置いて動かす                        |

## 使う

```sh
bun install
bun run dev        # 画面と中継を http://localhost:5173 で動かす
bun run node       # ノードを起動する。別の URL に接続するときは bun run node <URL>
```

初回はノードがコードを表示するので、画面にログインしてホームで入力する。トークンは `~/.hyph/node.json` に保存し、次回から自動で接続する。タスクの出力は中継に送らず、`~/.hyph/logs/<タスク番号>-<世代>.log` に残す。中継に送るのは終了コードだけである。ノードの実行には bubblewrap（`bwrap`）が必要。

## 候補を測る

最終目的はセッションごとに変わるため、課題と予算の基準はセッション名ごとに `~/.hyph/sessions/<セッション>.sqlite` に分けて保存する。モデルは `MODEL`・`REASONING` の環境変数で選び、サインインは `~/.hyph` で `bunx @earendil-works/pi-ai login openai` を実行して行う。

```sh
bun run measure <セッション> generate <最終目的のファイル> [検証用の数] [成績用の数]  # 課題を生成して選別する
bun run measure <セッション> review [件数]                                           # 課題を無作為に選んで表示する
bun run measure <セッション> run <コミット> [回数] [val|test]                         # 候補の成功率と費用を測る
```

課題は、模範解答が判定を通る・空の解答では通らない・最終目的に関係する、の3つを満たすものだけを表に入れる。最初の計測の費用を予算の基準として記録し、以降は1課題あたり基準の2倍を上限にする。
